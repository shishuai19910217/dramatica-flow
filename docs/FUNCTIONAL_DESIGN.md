## 1. 引言

### 1.1 文档目的

本文档详细描述 Dramatica-Flow 的功能设计，包括：
- 所有功能模块的定义和职责
- 各功能的输入输出规范
- 业务规则和交互流程
- 用户界面原型设计
- 状态流转和异常处理

### 1.2 功能设计原则

| 原则 | 说明 |
|------|------|
| **叙事质量优先** | 所有功能围绕保障叙事质量设计 |
| **状态一致性** | 确保世界状态在章节间正确累积 |
| **可追踪性** | 所有操作可审计、可回溯 |
| **易用性** | 提供 Web UI 和 CLI 两种交互方式 |
| **可扩展性** | 模块化设计，易于扩展新功能 |

## 3. 各功能详细描述

### 3.1 书籍管理模块

#### 3.1.1 创建书籍

| 属性 | 说明 |
|------|------|
| **功能描述** | 创建一本新的小说项目，初始化目录结构和配置文件 |
| **输入** | `title`: 书籍标题<br>`genre`: 小说类型（玄幻/仙侠/都市/历史等）<br>`chapters`: 预计总章节数<br>`words`: 每章目标字数<br>`forbidden`: 禁止词列表<br>`style_guide`: 风格指南 |
| **输出** | `book_id`: 书籍唯一标识<br>`title`: 书籍标题<br>`status`: 创建状态 |
| **业务规则** | 书籍标题不能为空<br>章节数必须 > 0<br>每章字数必须在 1000-20000 之间 |
| **交互流程** | 用户输入书籍信息 → 系统创建目录结构 → 初始化配置文件 → 返回成功 |

#### 3.1.2 删除书籍

| 属性 | 说明 |
|------|------|
| **功能描述** | 删除指定书籍及其所有数据 |
| **输入** | `book_id`: 书籍唯一标识 |
| **输出** | `ok`: 是否成功<br>`message`: 操作结果消息 |
| **业务规则** | 只能删除已存在的书籍<br>删除前需确认 |
| **交互流程** | 用户确认删除 → 系统删除目录 → 返回成功 |

#### 3.1.3 查看书籍列表

| 属性 | 说明 |
|------|------|
| **功能描述** | 获取所有书籍的基本信息 |
| **输入** | 无 |
| **输出** | `books`: 书籍列表（包含 id、title、genre、progress 等） |
| **业务规则** | 返回按创建时间排序的书籍列表 |
| **交互流程** | 用户请求 → 系统读取目录 → 返回列表 |

### 3.2 故事配置模块

#### 3.2.1 初始化配置模板

| 属性 | 说明 |
|------|------|
| **功能描述** | 为书籍创建配置模板文件（角色、世界、事件） |
| **输入** | `book_id`: 书籍唯一标识 |
| **输出** | `ok`: 是否成功<br>`files_created`: 创建的文件列表 |
| **业务规则** | 只能为已存在的书籍初始化<br>已存在的模板不会被覆盖 |
| **交互流程** | 用户请求 → 系统创建 JSON 模板 → 返回成功 |

#### 3.2.2 配置角色

| 属性 | 说明 |
|------|------|
| **功能描述** | 配置小说中的角色信息 |
| **输入** | `book_id`: 书籍唯一标识<br>`characters`: 角色列表，每个角色包含：<br>- `id`: 角色唯一标识<br>- `name`: 角色名称<br>- `role`: 角色职能（Protagonist/Antagonist 等）<br>- `personality`: 性格描述<br>- `need`: 双层需求（external/internal）<br>- `appearance`: 外貌描述 |
| **输出** | `ok`: 是否成功<br>`updated_count`: 更新的角色数量 |
| **业务规则** | 主角只能有一个<br>角色 ID 必须唯一 |
| **交互流程** | 用户编辑角色 JSON → 系统验证并保存 → 返回成功 |

#### 3.2.3 配置世界设定

| 属性 | 说明 |
|------|------|
| **功能描述** | 配置小说的世界观设定 |
| **输入** | `book_id`: 书籍唯一标识<br>`world`: 世界设定对象，包含：<br>- `name`: 世界名称<br>- `era`: 时代背景<br>- `geography`: 地理描述<br>- `rules`: 世界规则（魔法/武功/科技等）<br>- `cultures`: 文化设定<br>- `factions`: 势力列表 |
| **输出** | `ok`: 是否成功 |
| **业务规则** | 世界规则不能为空 |
| **交互流程** | 用户编辑世界 JSON → 系统验证并保存 → 返回成功 |

#### 3.2.4 加载配置到世界状态

| 属性 | 说明 |
|------|------|
| **功能描述** | 将配置文件加载到内存中的世界状态 |
| **输入** | `book_id`: 书籍唯一标识 |
| **输出** | `ok`: 是否成功<br>`loaded_characters`: 加载的角色数<br>`loaded_factions`: 加载的势力数 |
| **业务规则** | 必须先初始化配置模板<br>必须至少配置一个角色 |
| **交互流程** | 用户点击加载 → 系统读取 JSON → 初始化世界状态 → 返回成功 |

### 3.3 大纲管理模块

#### 3.3.1 AI 生成故事大纲

| 属性 | 说明 |
|------|------|
| **功能描述** | 根据配置自动生成完整的三幕式故事大纲 |
| **输入** | `book_id`: 书籍唯一标识<br>`prompt`: 额外提示（可选） |
| **输出** | `ok`: 是否成功<br>`outline`: 故事大纲对象 |
| **业务规则** | 必须先加载配置到世界状态<br>大纲包含四大关键锚点 |
| **交互流程** | 用户请求 → 系统调用 LLM → 解析结果 → 保存大纲 → 返回成功 |

#### 3.3.2 AI 续写故事大纲

| 属性 | 说明 |
|------|------|
| **功能描述** | 在已有大纲基础上继续生成后续内容 |
| **输入** | `book_id`: 书籍唯一标识<br>`current_chapter`: 当前章节位置 |
| **输出** | `ok`: 是否成功<br>`outline`: 更新后的故事大纲 |
| **业务规则** | 必须已有部分大纲<br>当前章节必须在已有大纲范围内 |
| **交互流程** | 用户请求 → 系统读取当前大纲 → 调用 LLM 续写 → 合并结果 → 返回成功 |

#### 3.3.3 AI 生成章节大纲

| 属性 | 说明 |
|------|------|
| **功能描述** | 根据故事大纲生成具体的章节大纲 |
| **输入** | `book_id`: 书籍唯一标识<br>`sequence_start`: 序列起始章节<br>`sequence_length`: 序列长度 |
| **输出** | `ok`: 是否成功<br>`chapter_outlines`: 章节大纲列表 |
| **业务规则** | 必须已有故事大纲<br>序列不能超出总章节数 |
| **交互流程** | 用户请求 → 系统读取故事大纲 → 调用 LLM 生成 → 保存章节大纲 → 返回成功 |

### 3.4 章节创作模块

#### 3.4.1 AI 写作（核心功能）

| 属性 | 说明 |
|------|------|
| **功能描述** | 执行完整的写作管线，生成章节内容 |
| **输入** | `book_id`: 书籍唯一标识<br>`chapter_number`: 章节号（可选，默认下一章）<br>`count`: 连续写作章节数（默认 1） |
| **输出** | `ok`: 是否成功<br>`chapters_written`: 成功写入的章节数<br>`results`: 每章的写作结果 |
| **业务规则** | 必须先有章节大纲<br>章节号必须在有效范围内<br>连续写作最多 10 章 |
| **交互流程** | 用户请求 → 快照备份 → 建筑师规划 → 写手写章 → 验证 → 审计 → 修订 → 更新状态 → 返回成功 |

#### 3.4.2 AI 重写段落

| 属性 | 说明 |
|------|------|
| **功能描述** | 重写指定章节的某个段落 |
| **输入** | `book_id`: 书籍唯一标识<br>`chapter_number`: 章节号<br>`start_index`: 段落起始位置<br>`end_index`: 段落结束位置<br>`style`: 重写风格（可选） |
| **输出** | `ok`: 是否成功<br>`rewritten_text`: 重写后的文本 |
| **业务规则** | 章节必须已存在<br>位置范围必须有效 |
| **交互流程** | 用户选择段落 → 系统调用 LLM 重写 → 返回结果 → 用户确认后保存 |

## 6. 异常处理机制

### 6.1 异常分类

| 异常类型 | 说明 | 处理策略 |
|----------|------|----------|
| **配置错误** | 配置文件缺失或格式错误 | 提示用户检查配置 |
| **输入验证错误** | 参数不符合要求 | 返回详细错误信息 |
| **LLM 调用失败** | LLM 服务不可用或超时 | 重试机制（最多 3 次） |
| **JSON 解析失败** | LLM 返回格式错误 | 自动修复或降级处理 |
| **文件操作失败** | 文件读写失败 | 回滚并提示用户 |
| **权限错误** | 无权限访问文件 | 提示用户检查权限 |
| **网络错误** | 网络连接失败 | 提示用户检查网络 |

### 6.2 错误处理流程

```
用户操作 ──▶ 参数验证 ──▶ 业务逻辑执行 ──▶ 结果返回
                 │              │
                 ▼              ▼
            参数错误       业务异常
                 │              │
                 ▼              ▼
         返回错误信息     记录日志 + 返回错误信息
```

### 6.3 重试机制

```python
# LLM 调用重试逻辑
def call_llm_with_retry(prompt, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = llm_client.chat.completions.create(...)
            return response
        except Exception as e:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # 指数退避
                continue
            raise e
```

### 6.4 错误响应格式

```json
{
    "ok": false,
    "error": {
        "code": "LLM_CALL_FAILED",
        "message": "LLM 服务调用失败",
        "details": "连接超时，请稍后重试",
        "suggestion": "检查网络连接或尝试更换 LLM 后端"
    }
}
```
